# 1-day-life-time

## FreshGenerator: воспроизводимая проверка Fabric

Репозиторий предоставлен владельцем для тестирования присланного мода. Здесь хранится **исходный, неизменённый JAR** и независимый проверяющий скрипт. Исправления в мод не вносились.

Проверяемый файл: `mods/FreshGenerator-00093076.jar` (494984 байта).

SHA-256: `00093076e1364a61ec5d4d847444371597e87a963b7539dd4c1ee96714b49dc6`.

### Что делает Actions

1. Проверяет хеш JAR, скачивает закреплённые официальные Minecraft 26.3 / Fabric Loader 0.20.1 и Fabric API 0.166.2+26.3; проверяет хеши зависимостей.
2. Запускает настоящий dedicated Fabric server на Java 25 с оригинальным модом, без дополнительных тестовых модов и преобразования его классов.
3. Создаёт отдельный мир seed 0 через `minecraft:normal`; из сохранённых данных проверяет, что реально выбран `freshgenerator:highlands_v2`.
4. Генерирует четыре выбранных чанка, ждёт FULL, сохраняет, останавливает сервер, повторно открывает мир и проверяет сохранённые чанки.
5. Печатает итог и диагностические логи в Actions и Job Summary. Сравнение хешей секций после reopen сохраняется как отдельное свидетельство; тики могут законно менять состояния.

Точки: граница биомов X−3424/Z4704; сухой пояс X337339/Z256103; спорный lookup X337280/Z256046; океанское поднятие X−359652/Z480144.

Сервер слушает только `127.0.0.1:25595`; RCON/query/status отключены. Скрипт ограничен 900 секундами, использует до 2 GiB Java heap и два процессора. Мир существует только для проверки; bootstrap создаёт `eula=true` для запуска официального сервера. Существующие миры скрипт по умолчанию отвергает.

### Запуск локально

Нужны Java 25 и Python 3.10+ (только стандартная библиотека Python):

```bash
python3 tests/fabric_smoke.py --java java --mod mods/FreshGenerator-00093076.jar --config tests/pinned_config.json --work .audit-world --max-seconds 900
```

`--work` должна быть новой пустой папкой. Выходной `smoke_result.json` содержит события, проверенные зависимости, фактические worldgen settings и FULL-чанки. `tests/inspect_saved_chunks.py` дополнительно экспортирует блоки и сохранённые quart-биомы.

### Границы проверки

Успех означает запуск, выбранный генератор, FULL-генерацию перечисленных мест и save/reopen. Он не доказывает реализм всех биомов, корректность всех структур, работу при любых сидах, длительных тиках или многопользовательской нагрузке. Подробный научный аудит, карты и миллионы измерений предоставляются отдельным отчётом.

Minecraft/JDK/Fabric-бинарники и миры в этот репозиторий не включены. Проверяющий код независим от исходного проекта мода; авторские права на мод остаются у его правообладателя.

### Дополнительный контроль R4: порядок генерации

Отдельная задача `generation-order` создаёт два свежих мира seed 0. В каждом запрашиваются те же 18 FULL-чанков: сетка 3×3 около X337280/Z256046 (пограничный климатический lookup) и 3×3 около X−286865/Z22820 (морская температурная граница). Порядок запросов во втором мире обратный. До целей сервер получает нативную команду `tick freeze`; обычные изменения от игровых тиков исключены из целевого сравнения.

Сравниваются декодированные состояния всех блоков, quart-биомы, heightmaps, structures и block_entities. Порядок палитры и способ упаковки не считаются изменением мира. Это ограниченный тест двух областей; он не контролирует каждую внутреннюю очередь фоновых стадий Minecraft и не доказывает детерминизм всех сидов.

```bash
python3 tests/generation_order.py --java java --mod mods/FreshGenerator-00093076.jar --work .audit-order
```

Результат, точные количества и хеши выводятся как `ORDER_RESULT` в журнал и Job Summary. Различие является сигналом для расследования, а не автоматическим доказательством дефекта именно мода. Исходный save/reopen контроль сохранён отдельной задачей.
